## 1. 仿真小车的启动文件路径

**结论：`fishbot_nav` 与 `fishbot_motion_control_microros` 内没有 Gazebo 仿真启动文件。**

`fishbot_nav` 提供的是实车/上位机启动：

| 用途 | 路径 |
|---|---|
| 实车一键 bringup（URDF→TF、odom→TF、micro-ROS Agent、雷达） | `fishbot_nav/src/fishbot_bringup/launch/bringup.launch.py` |
| 仅 URDF 发 TF | `fishbot_nav/src/fishbot_bringup/launch/urdf2tf.launch.py` |
| Nav2 | `fishbot_nav/src/fishbot_navigation2/launch/navigation2.launch.py` |
| Cartographer 建图 | `fishbot_nav/src/fishbot_cartographer/launch/cartographer.launch.py` |

README 给出的运行示例是导航，不是仿真：

```text
ros2 launch fishbot_navigation2 navigation2.launch.py use_sim_time:=False
```

出处：`fishbot_nav/README.md` 第 32–35 行。

**补充（第三份官方仓库，手册第 5 章已点名）：**

带差速插件和雷达插件的教学仿真 URDF 在：

```text
https://github.com/fishros/fishbot 分支 humble
路径：src/fishbot_description/urdf/fishbot_gazebo.urdf
启动示例（官方教学常用）：ros2 launch fishbot_description gazebo.launch.py
```

`fishbot_nav` 里的 `fishbot.urdf` **不能**当仿真车：只有圆柱车体和雷达 link，没有轮子关节，也没有 Gazebo 插件。

本仓库仿真实际采用：从教学模型复制到 `ros2_ws/src/move_car_description/urdf/move_car.urdf`，由 `move_car_simulation/launch/simulation.launch.py` 启动。

## 2. 底盘话题：速度、里程计、IMU

固件默认值在 `fishbot_motion_control_microros/include/fishbot_config.h`：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `twist_topic` / CMD_VEL | `cmd_vel` | 订阅 `geometry_msgs/Twist` |
| `odom_topic` | `odom` | 发布 `nav_msgs/Odometry` |
| `odom_frameid` | `odom` | `/odom` 的 `header.frame_id` |
| `odom_c_frameid`（默认宏） | `base_footprint` | `/odom` 的 `child_frame_id` |
| 节点名 | `fishbot_motion_control` | |
| 域 ID | `0` | |

出处：`fishbot_config.h` 约 83–90 行；读写实现见 `src/fishbot_config.cpp`。

**与计划书「官方预期」的差异：**

| 话题 | 计划书预期 | 仓库实际默认 | 本机实车曾观察到 |
|---|---|---|---|
| 速度 | `/cmd_vel` | `/cmd_vel`（相对名 `cmd_vel`） | 一致 |
| 里程计 | `/odom` | `/odom` | 一致 |
| IMU | `/imu/data` | **`/imu`**（代码写死话题名 `"imu"`） | `/imu`，不是 `/imu/data` |

IMU 发布代码：

```text
fishbot_motion_control_microros/src/fishbot.cpp
约 309–312 行：rclc_publisher_init… 话题 "imu"
约 280 / 547 行：imu_msg.header.frame_id = "imu"
```

话题名可在板子配置里改 `twist_topic` / `odom_topic`；IMU 话题在当前固件源码中固定为 `imu`。

QoS：实车 `/odom`、`/imu` 为 Best Effort（与 `docs/问题记录.md`、验收时一致）。上位机 `odom2tf` 使用 `SensorDataQoS()` 订阅 `odom`：

出处：`fishbot_nav/src/fishbot_bringup/src/odom2tf.cpp` 第 11–13 行。

通信：默认 `udp_client`，Agent 端口默认 `8888`（`CONFIG_DEFAULT_TRANSPORT_MODE_WIFI_SERVER_PORT`）。`bringup.launch.py` 启动 `micro_ros_agent udp4 --port 8888`。

## 3. TF 树与 laser 相对车体

### 3.1 官方 `fishbot_nav` 模型 TF（静态，来自 URDF）

文件：`fishbot_nav/src/fishbot_description/urdf/fishbot.urdf`

```text
base_footprint
└── base_link          joint origin xyz="0 0 0.076"
    ├── laser_link     joint origin xyz="0 0 0.075"  rpy="0 0 0"
    └── laser_frame    joint origin xyz="0 0 0.075"  rpy="0 0 0"
```

- `laser_link` 与 `laser_frame` 相对 `base_link` 同为上方 0.075 m，朝向与车体一致（rpy 全 0）。
- 该 URDF **不包含**左右轮 link，也 **不发布** `odom → base_footprint`。

### 3.2 里程计 TF（动态）

`odom → base_footprint`（或消息里的 `child_frame_id`）由节点 `odom2tf` 根据 `/odom` 广播：

出处：`fishbot_nav/src/fishbot_bringup/src/odom2tf.cpp` 第 22–34 行；由 `bringup.launch.py` 启动。

完整实车目标树（官方 bringup 意图）：

```text
map                    （SLAM / AMCL）
└── odom               （odom2tf ← /odom）
    └── base_footprint
        └── base_link
            ├── laser_link / laser_frame
            └── （实车雷达驱动常另设 laser_frame）
```

鱼香雷达驱动教程里 RViz Fixed Frame 常用 `laser_frame`；与 URDF 里同时存在的 `laser_link` 不是同一概念时，要以当前驱动发布的 `header.frame_id` 为准。本仓库仿真统一用 `laser_link`，`/scan` 的 `frame_name` 为 `laser_link`。

### 3.3 与计划书对照

计划书写的是 `base_link → laser`。官方 URDF 实际名字是 **`laser_link`**（另有同位置的 `laser_frame`）。后续本仓库应以 `laser_link` 为准，避免混用 `laser`。

## 4. 轮距、轮径、车体外形

| 量 | 数值 | 来源 |
|---|---|---|
| 车体视觉 | 圆柱，半径 **0.10 m**，高 **0.12 m** | `fishbot.urdf` 第 10 行 |
| `base_link` 离地 | **0.076 m** | `fishbot.urdf` `base_joint` origin |
| 雷达相对 `base_link` 高度 | **0.075 m** | `fishbot.urdf` `laser_joint` |
| 轮径 | **65 mm**（0.065 m） | 固件默认 `CONFIG_DEFAULT_MOTOR0_PARAM_WHEEL_DIAMETER`，`fishbot_config.h` 第 43 行 |
| 轮距 | **172.75 mm** | 固件默认 `CONFIG_DEFAULT_KINEMATIC_WHEEL_DISTANCE`，`fishbot_config.h` 第 48 行 |
| 发货外壳 | 约 **188 × 199 × 110 mm** | 计划书 / 发货资料（非上述仓库） |

不一致处：

- 官方导航 URDF 是教学用圆柱，**不是**发货长方体外壳。
- 固件默认轮距 172.75 mm；教学 Gazebo 模型（`fishbot` humble）常见轮距约 0.20 m（左右轮 y=±0.10）。本仓库仿真曾沿用教学 0.20 m，实车应以实测或固件配置为准，并保证 URDF 关节 y 与差速参数一致。

`fishbot_nav` 的 URDF **没有**轮距/轮径字段；运动学尺寸以底盘固件配置为准。

## 5. 哪些只作参考，哪些要写进自己的包

### 只作参考（不直接当本仓库可运行仿真）

| 文件/包 | 原因 |
|---|---|
| `fishbot_nav/.../fishbot.urdf` | 无轮、无 Gazebo 插件，不能仿真 |
| `fishbot_nav` 整仓 Nav2 / Cartographer 参数 | 可对照组织方式；本仓库自建 `move_car_navigation` |
| `fishbot_motion_control_microros` 电机/PID/GPIO 实现 | 不重写底盘固件，只对接话题 |
| 官方 `bringup.launch.py` 里的雷达串口映射假设 | 实车雷达用 USB / 自有驱动时需另配 |

### 要写进（或已写入）自己的包的参数与约定

| 内容 | 落到本仓库 |
|---|---|
| 接口：`/cmd_vel`、`/odom`；IMU 实车为 `/imu`，仿真可用 `/imu/data` | 计划书 + launch remap / 文档约定 |
| TF：`odom → base_footprint → base_link → laser_link` | `move_car_description` URDF；仿真差速插件发 odom TF |
| 轮径 0.065 m、轮距（教学 0.20 或固件 0.17275，实车实测替换） | URDF + 差速插件 |
| 车体外形：发货盒子 / 实测替换圆柱 | URDF visual/collision |
| 雷达高度与朝向：初值可参考 0.075 m，实车实测 | `laser_joint` |
| micro-ROS Agent：`udp4 --port 8888`，域 0 | 实车 bringup；仿真用域 42 隔离 |
| Nav2 / SLAM 参数结构 | 可参考 `fishbot_navigation2/config/nav2_params.yaml`，自维护副本 |

### 许可证

两仓库均声明学习参考、非授权禁止商用（见各自 `README.md` / `LICENSE`）。复制 URDF 或参数到本仓库时，保留出处与版权声明。
